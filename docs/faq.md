# 常见问题解答 (FAQ)

## 一般问题

### 这个工具是免费的吗？

是的，ImageMinify 是完全免费和开源的，根据 MIT 许可证发布。

### 支持哪些操作系统？

ImageMinify 支持 Windows 10 及以上版本（基于 WPF 框架）。

### 需要安装 .NET 运行时吗？

如果您下载的是自包含（Self-Contained）版本，则不需要额外安装。如果下载的是依赖框架版本，需要安装 [.NET 10 运行时](https://dotnet.microsoft.com/download/dotnet/10.0)。

## 功能问题

### 支持哪些图片格式？

- **输入格式**：JPEG (.jpg, .jpeg)、PNG (.png)、BMP (.bmp)、WebP (.webp)
- **输出格式**：JPEG、PNG、WebP，或保持原格式

### 压缩是否会降低图片质量？

取决于格式和设置：

- **JPEG**：有损压缩，由质量滑块控制程度；MozJPEG 后处理是无损的
- **PNG**：质量 95 以下走调色板量化（有损，视觉差异通常不明显），95 及以上逐像素无损；oxipng 后处理是无损的
- **WebP**：有损压缩，同等观感下通常比 JPEG 小 25–35%

### 压缩后的文件保存在哪里？

由「输出位置」决定，共四种：

- **加后缀**：与原文件同目录，文件名加 `_compressed`（后缀可以改）
- **子文件夹**：原目录下的 `compressed` 文件夹，文件名不变
- **指定目录**：写到所选目录，并保留原有的目录层级
- **覆盖原图**：直接替换原文件

前三种都不会改动原文件。

### 覆盖模式安全吗？

覆盖是不可撤销的，被替换的文件不会进回收站。因此界面会全程显示当前处于覆盖模式，并在每次开始前额外确认一次。

写入本身是安全的：程序先把完整结果写到同目录的临时文件，再原子替换目标文件，所以中途取消、崩溃或断电都不会留下写坏一半的图片 —— 要么是新文件，要么还是原文件。

### 压缩后文件反而变大了？

对已经优化过的图片重新编码经常会这样，这是编码本身的性质，不是 bug。默认开启的「跳过变大的图片」会在这种情况下保留原文件，并把该行标记为「已跳过」。

一个例外：当您明确要求转换格式时，即使变大也会照做 —— 您要的是那个格式，程序不该擅自决定不给。

### 「目标大小」是怎么工作的？

填入目标 KB 后，引擎在质量 5–100 之间做二分查找，找出能落在该体积以内的最高质量，一般 6–7 次试压就能定下来。试压用的是较快的编码档位，确定质量后再用最佳档位正式输出，因此最终文件只会比试压结果更小、不会更大。

如果该格式在最低质量下仍然超标，程序会输出它能做到的最小文件，并在结果里标注未达成目标，而不是悄悄返回一个远超预算的文件。这时可以配合缩小尺寸，或改用 WebP。

### 带透明的 PNG 会被压成不透明吗？

不会。量化时会根据图片是否含有 alpha 通道选择算法：有透明就用能保留四个通道的量化器，没有透明才用在不透明图上效果更好的那个。图标、logo 这类图片压缩后透明区域保持原样。

### 元数据是怎么处理的？

- **勾选「清除元数据」**：EXIF、IPTC、XMP 与色彩配置全部删除，JPEG / PNG / WebP 三种格式都会真正写出干净的文件
- **不勾选**：并非原样保留，而是**精简**为相机品牌、型号、软件与拍摄时间四项，GPS 坐标、缩略图、镜头序列号等一并去掉

无论哪种设置，方向标记都会在读取时直接应用到像素上并复位，所以压缩后的图片在任何看图工具里都不会再转向。

要把照片发到公开场合，勾上「清除元数据」即可去掉 GPS 位置。

### 有文件大小限制吗？

理论上没有严格限制，但处理超大图片（如 50MB 以上）会明显增加内存占用和处理时间。并行线程数最多 16，同时解码的位图越多占用越高。

### 什么是 imagequant、MozJPEG 和 oxipng？

- **imagequant**：高质量 PNG 量化库，同等观感下调色板质量优于内置量化器
- **MozJPEG**：Mozilla 的 JPEG 编码器，无损重排霍夫曼表与扫描顺序，通常再省 5–15%
- **oxipng**：PNG 无损二次优化，重新压缩数据流并清理冗余块

三者都是可选的。没有它们程序照常工作，只是压缩率略低。界面右下角的「压缩引擎」区域会显示当前实际生效的是哪一个。

## 技术问题

### 为什么某些 PNG 文件压缩效果不明显？

PNG 本身已是压缩格式。已经优化过的 PNG、或者颜色数很多的照片型 PNG，能挤的空间本就有限。把质量降到 95 以下启用量化通常能带来明显收益；如果图片本来就在 256 色以内，量化也没有什么可省的。

另外，平滑渐变是量化最不划算的一类图 —— PNG 的行过滤器本就能把它压得很好，量化反而引入色带让 zlib 更难压。

### 我的杀毒软件报警了怎么办？

如果您从官方 Release 下载，程序是安全的。部分杀毒软件可能对自包含 .NET 应用产生误报。您可以查看源代码进行验证，或将程序添加到杀毒软件的白名单中。

### 应用程序崩溃了怎么办？

请尝试以下步骤：

1. 重新启动应用程序
2. 尝试处理较少的文件
3. 检查是否有足够的磁盘空间
4. 如果问题持续，请在 [GitHub Issues](https://github.com/Moresyl/ImageMinify/issues) 报告，并提供详细的错误信息和重现步骤

单张图片失败不会中断整批 —— 该行会标为失败并附上原因，其余文件照常处理完。

### 设置保存在哪里？

`%AppData%\ImageMinify\settings.json`。删掉这个文件即可把所有偏好恢复到默认值。

### 之前的重命名功能去哪了？

已在 v3.0.0 移除。压缩工具的职责是压缩，批量重命名交给专门的工具做得更好，两件事混在一个界面里只会让参数区变得难以看懂。
