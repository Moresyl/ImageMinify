# 压缩保真与启动修复

针对 issue #1，主窗口引用的 `InsetPanel` 并不存在，已改用现有 `Inset` 样式。
启动阶段失败会显示独立系统对话框、写入 `%LOCALAPPDATA%/ImageMinify/Logs/startup-error.log`
并退出；不再尝试在尚未显示的窗口内展示错误。资源回归测试同时检查静态键和实际 WPF 窗口构造。

参考 SnapImg 的候选比较与解码校验思路，本项目保留自身桌面架构和质量滑块：

- PNG 同时衡量真彩无损和调色板候选，只接受更小且通过解码校验的调色板结果。
- 常规调色板不合格时，最终编码最多补试一次 256 色、无抖动的 Wu 候选，继续使用相同的 Alpha、局部和整图质量门槛；快速体积搜索不增加该次编码。
- 两个调色板候选都不合格时，8 位 PNG 的最终有损编码可补试一次真彩 RGB 精度候选：质量 85–94 每通道最多改变 2，较低质量最多改变 4，保持 Alpha 和全透明像素隐藏 RGB；解码回读后仍须通过全部质量门槛且比无损更小。质量 95–100 和 16 位 PNG 不走此路径。
- 质量 95–100 的静态 PNG 若实际不超过 256 种 RGBA 颜色，会尝试精确源色调色板；必须回读后所有 RGBA 样本完全相同且体积更小才采用。动画仍沿用原无损路径。
- 调色板输出必须保持每个像素的 Alpha，限制单像素显示误差并检查整图及每个 8×8 分块的均方误差；边缘不足 8×8 的区域按实际像素数计算，动画逐帧检查。不合格则回退无损候选，避免小图标或文字的局部损伤被大面积背景平均掉。
- PNG 高质量路径显式保留 RGBA，包括完全透明像素下的 RGB；WebP 无损也保留隐藏 RGB。
- BMP 按实际透明度选择 32 位或 24 位输出，避免原格式压缩把透明/半透明图片变为不透明。
- 16 位 PNG 保持 PNG 输出时使用 Rgba64 解码和 16 位无损编码，保留 RGB/Alpha 低位精度。质量滑块不会降低该路径的位深；目标体积无法达到时报告未达标。
- 16 位静态不透明 PNG 使用 RGB 输出，省去冗余 Alpha 通道。16 位动画逐帧独立编码并按 APNG 规范组装，避开 ImageSharp 3.1 动画帧去重经过 Rgba32 导致的低位丢失；保留帧延迟、循环次数及独立封面。完整帧使用 Source 混合，可能比差分帧输出更大。
- 取消信号传入候选处理：PNG 候选之间、真彩候选逐行处理及 16 位动画逐帧/逐块检查取消；底层单次同步编码仍需返回后才能退出，取消时释放临时图片且不写入结果文件。
- PNG、JPEG、WebP 清理个人元数据时保留 ICC 显示配置。后处理工具不再删除已保留的颜色信息。
- 显式清理元数据时，即便结果更大也不返回含原始隐私信息的源文件。
- 外部优化工具的两个输出管道均异步读取，避免因管道填满而卡住批量处理。
- 非覆盖模式写入时原子检查目标名称，重名自动添加编号，避免同名不同格式批量转换或重复运行覆盖既有文件；只有明确选择覆盖模式才替换源文件。
- 目标体积搜索保留已经达标的编码结果；同质量的完整编码更大时不丢弃较小候选，最终最低质量编码达标时也按实际字节报告成功。

这是针对现有桌面编码路径的适配，另外补充了 PNG 到 PNG 的 16 位样本保留；不代表移植了 SnapImg 全部编码器、HDR 显示元数据处理或性能门禁。16 位 PNG 转 JPEG/WebP 仍受这些输出编码器的 8 位能力限制。
质量检查衡量当前样本空间中的显示差异，不是对所有色彩空间的感知质量保证；目标体积搜索仍为有界近似搜索。

验证命令：`dotnet test ImageMinify.sln -c Release`。
WPF 加载测试覆盖当前 Windows 环境；Windows 10 22H2 的安装包实机验证仍需独立进行。
